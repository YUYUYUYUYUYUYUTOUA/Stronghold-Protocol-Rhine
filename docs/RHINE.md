# 莱茵生命 · 联合科研（非官方扩展）

本扩展基于 [sganggs/Stronghold-Protocol](https://github.com/sganggs/Stronghold-Protocol) v0.1.1，并合入至 `8b10625` 的后续修复，保留原玩法并加入莱茵生命研究路线。修改日期为 2026-10-04。它是独立同人扩展，不是上游官方更新；修改范围见 [RHINE-CHANGES.md](RHINE-CHANGES.md)。

新增 IV 阶乌啾（灵巧、协防干员）承接白面鸮的“进入休整期”前方特质复制；新增 V 阶森蚺（独行、萨尔贡）承接塞雷娅的“休整期结束”前方特质复制。

四位新增干员在“干员调配”中选择技能与模组。梅尔、乌啾各 2 个技能，森蚺、伊芙利特各 3 个技能；模组种类分别为 1、1、2、2。默认配置：梅尔 S1“迷惑装置”、SUM-X；乌啾 S2“捉迷藏”、XAH-X；森蚺 S3“钢铁意志”、HES-X；伊芙利特 S2“炎爆”、BLA-X。模组只由精锐装备。

沿用原项目阶数配置：这四位普通干员技能 Lv.4，精锐技能 Lv.7、模组 Lv.1。数据与效果依据 [梅尔](https://prts.wiki/w/梅尔)、[乌啾](https://prts.wiki/w/乌啾)、[森蚺](https://prts.wiki/w/森蚺)、[伊芙利特](https://prts.wiki/w/伊芙利特) 核对，并使用固定版本客户端数据构建。森蚺特限模组 RA-α 已从可选项移除，旧配置会回退 HES-X。梅尔模组说明为“首个召唤物不占部署位；不过卫戍召唤物本来就不占人口，所以这条效果没了XP”。其他手动选择的有效技能或模组仍然保留，不会被新默认值覆盖。

梅尔普通时提供 1 只机械水獭，精锐时提供 2 只；库存及同时部署上限均随此规则调整，所有技能和模组配置一致。机械水獭不接受干员治疗，包括塞雷娅及赫默医疗无人机等由干员提供的治疗；科研装置“生命维持仪”仍可治疗它。无干员治疗来源的自然回复不受这条限制。

莱茵盟约图标使用 `public/art/rhine/bond.svg`：根据用户提供的莱茵生命标志绘制纯白、透明、无文字的 ∞ / ＋ / － 轮廓，与现有阵营图标的单色风格一致。内置 imagegen 用于生成预览（提示为“保留∞＋－、纯白、透明底、去掉英文”）；预览的透明区域存在杂点，最终游戏资产采用清晰的矢量轮廓。

## 阵营装备

| 装备 | 阶数 | 普通 / 精锐基础属性 | 科研效果 |
| --- | --- | --- | --- |
| 莱茵实验终端 | III | 攻击力 +15% / +25% | 己方莱茵生命激活时，携带者每 10 层科研获得 2 / 3 攻速，最多 20 / 30。 |
| 联合研究主机 | VI | 生命上限 +45% / +70% | 莱茵生命携带者在场时，己方每台已部署科研装置每层科研额外获得 1 点基础攻击，最多 100；携带者同时装备实验终端时变为每层 2 点，最多 200。此效果普通与精锐相同。 |

两件装备均进入对应阶数的商店与通用装备奖励池，普通售价分别为 2、4 资金；两件同名普通装备合成为一件精锐，也支持原有装备升级效果。基础属性对所有携带者有效。多个主机只取当前最强的增益，不叠加；主机持有者离场后重新计算。主机增益计入装置基础攻击，伊芙利特继承该数值；增益只取科研层数，不读取装置当前攻击力，避免循环。

实验终端本身不赋予莱茵生命盟约。与“变形同构体”同时装备时，携带者才额外获得莱茵生命；普通与精锐终端均支持。主机没有转职效果。

装备图标为本扩展生成的透明 PNG：`public/art/rhine/terminal.png` 与 `public/art/rhine/mainframe.png`，提示和来源见 [生成记录](rhine-equipment-art.json)。

## 科研装置

莱茵人数达到 3 时获得三种装置，各有一个独立科研备牌位，可以部署一台；达到 6 时可以部署两种不同装置；达到 9 时可以同时部署全部三种装置。科研位不占普通备牌格，装置不占干员人数，但占一个可部署格。装置无敌、不被敌人选中、不阻挡，不能出售、装备或赠送。

备战期可以随时更换、撤回和重新摆放。人数掉档时自动收回超出的装置；再次激活保留原来的装置和研究点。

所有装置基础攻击：**300 + 莱茵层数 × 3**，另加符合位置条件的梅尔增益及己方最强的联合研究主机增益。

医疗装置治疗、能量装置脉冲及伊芙利特继承均读取这个基础攻击，不读取临时攻击增益；治疗与伤害的结算倍率仍正常生效。

| 装置 | 原型 | 第一次突破 | 第二次突破 |
| --- | --- | --- | --- |
| 生命维持仪 | 每 3 秒，治疗半径 2 格内己方生命比例最低的单位，治疗量为装置攻击的 50%。 | 溢出治疗的 50% 转为 6 秒护盾，同源盾累计不超过目标生命上限。 | 每次治疗两个目标。 |
| 能量谐振仪 | 半径 2 格内己方干员发动技能时充能，每 3 次对附近敌人释放 120% 攻击的法术脉冲。单个干员 3 秒内最多充能一次。 | 脉冲影响目标周围 1 格。 | 脉冲伤害再提高 50%。 |
| 生态调控器 | 每 8 秒产生持续 4 秒的区域，半径 2 格。减速为 25% + 每层 0.1%，最高 65%。 | 区域启动时束缚 1 秒。 | 区域半径增加 1 格。 |

层数决定日常数值，参战研究点只决定阶段突破。成功 +2 点、失败 +1 点，每阶段均需要 **5 点**：原型攒满 5 点变为改良型，再重新攒满 5 点变为成熟型。每次突破立即清零，溢出点数不保留（例如 4 点时成功，突破后为 0 点）；成熟型不再积累研究点。阶段单独保存，清零不退级。普通回合以主战无漏怪作为成功，领袖回合按共同胜负结算。只有该回合主战真正部署的装置获得研究点；预览、拖动、重连和联防续战不重复结算。

装置使用三张独立透明贴图：双旋翼医疗探机、线圈谐振塔、生态培养舱。场上有各自的待机和技能触发动态；突破阶段同时反映在装置灯效中。贴图参考原游戏召唤物的机械结构与画面比例，为本扩展新绘制。

选中或预放置装置时，棋盘显示整格作用范围，不再绘制圆圈。基础半径 2 格时包含中心在欧氏距离 2 格内的 13 格；生态突破Ⅱ为半径 3 格的 29 格，不随朝向变化。边缘越界格不显示，范围适配高台及镜像阵地。实际充能、治疗、选敌与生态作用使用同一格子判定；移动单位按当前所在格判定，巨型敌人任一占据格进入范围即可受影响。能量脉冲的溅射另按目标周围欧氏距离 1 格计算。

能量谐振仪下方显示技能条样式的充能进度，依次为 0 / 3、1 / 3、2 / 3，满 3 点攻击后回到 0；重连或观战同步当前进度。每次发射都有装置闪光、指向目标的光束和命中效果，低画质也保留明确反馈。科研备牌卡与详情面板同步说明当前范围。尚无战斗实时属性时，详情的 300 攻击明确标为“基础攻击”，未计科研层数、装备或梅尔增益。

可复现的界面验收地址为 `/dev/game-mock.html?phase=PREP&variant=rhineRange&researchDevice=ecology&researchStage=2`；该开发场景提供成熟生态装置及四件普通／精锐科研装备，仅用于界面检查。

### 文件与运行

- 共用参数：`shared/rhineResearch.js`。
- 数据与特质文字：`tools/rhine-data.mjs`，修改后运行 `node tools/rhine-data.mjs`；完整 `npm run build-data` 也会应用本扩展。
- 四位干员战斗入口：`server/sim/content/kits/rhine.js`，具体技能分别在 `rhineSupport.js` 与 `rhineAssault.js`。
- 装置、梅尔、塞雷娅和伊芙利特科研效果：`server/sim/content/rhine.js`。
- 白面鸮叠层：`server/sim/content/rhineMeta.js`。
- 部署限制、研究点：`server/match/PlayerState.js` 与 `Match.js`。
- 资源补全：`node tools/fetch-rhine-assets.mjs`。干员头像、立绘、技能图标及 Spine 使用原项目同源资源；三个装置使用本扩展通过 imagegen 新绘制的透明 PNG 与程序动画，盟约及后备图标为 SVG。机械水獭使用上游提供的同角色 `ghost_1` 模型。

首次从源码运行：
```powershell
npm ci
npm run setup
npm start
```

`setup` 调用已包含莱茵资源计划的通用下载器。已有原版资源时可单独运行 `node tools/fetch-rhine-assets.mjs` 补全扩展资源。扩展数据已经提交，无需为了正常游玩重新构建；修改扩展数据后运行 `node tools/rhine-data.mjs`，再执行 `npm test`。

默认浏览器地址为 `http://127.0.0.1:3000/`。需要使用启动器并指定监听范围时，可在项目目录执行：

```powershell
node scripts/launch.mjs --port 3000 --host 127.0.0.1 --no-setup
```

仅本机游玩或使用本机隧道时可监听 `127.0.0.1`；需局域网直连时改为 `--host 0.0.0.0`，并按 [DEPLOY.md](DEPLOY.md) 配置防火墙。穿透或反向代理应转发选定端口及 `/ws` WebSocket，不要把私人隧道地址或认证令牌提交到仓库。

更新前备份当前版本，在现有对局全部结束后停止旧服务，再安装新版依赖、检查资源并启动。启动器不会自动替换已占用同一端口的服务。客户端和服务端须使用同一份代码与数据，更新后刷新网页再开新房间。回退时停止新版并从备份目录启动；对局保存在进程内存中，重启或回退都不能恢复已结束的旧进程对局。

### 验证记录与边界

森蚺沿用本扩展初版的自动施放约定：S2／S3 满技力且准备攻击时施放。本次迁移没有将她改为上游部分重装的“受到伤害时”施放。

本次科研更新的全量回归为 3515 项：3506 通过、0 失败、9 项条件跳过（原始数据缓存或可选浏览器环境）。科研机制专项覆盖水獭全部技能／模组数量、干员禁治疗与医疗装置例外、同名产层、九人容量及掉档回收、整格作用与充能快照。另以实际 Chromium 检查范围、充能和攻击画面；整合包启动、资源完整性及 HTTP／WebSocket 另行验收。此记录不代表完整人工多人对局验收或远程 CI 已通过。
