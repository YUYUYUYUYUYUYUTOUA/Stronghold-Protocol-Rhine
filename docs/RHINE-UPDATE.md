# 联网更新与配置保留

从 **v0.1.3-rhine.5** 起，双击安装目录的 **更新旧版.bat** 或 **联网更新.bat**，即可自动获取本扩展 GitHub Releases 的正式最新版。两个入口功能相同，不需要每次手动下载、解压完整包。

## 普通玩家怎么更新

1. 等所有对局结束，关闭原启动窗口。使用开机自启的用户先停止对应服务，防止更新时重新启动。工具不会停止或启动服务。
2. 双击原目录的 **更新旧版.bat**。工具自动识别安装目录，检查正式最新版，下载并校验完整包。
3. 全部检查通过后，工具在原目录的 `.rhine-updates\时间-编号\` 备份本次替换或删除的文件，再原地安装新版。已有用户改动与新版冲突时会停止，不覆盖这些改动。
4. 看到“更新完成”后，从**原安装目录**启动游戏，继续使用原来的访问地址。

同一安装一次只开一个更新窗口。已是最新版时提示无需更新。更新工具自身也随完整包更新。

当前正式版为 **v0.2.2-rhine.1**，同步上游0.2.2，并保留卡兹戴尔众魂、战争巨炮和莱茵科研装置。带清单的 **v0.2.1-rhine.4** 及更早莱茵包可以跨版本直接更新；本地配置、冲突保护、备份与回退规则保留。新版潜能与练度默认满加成，两种数据档分别保存调配偏好。

### 较早版本如何接入

较早包没有联网入口，或“更新旧版.bat”仍需手动选择新包。只需从 [最新 Releases](https://github.com/YUYUYUYUYUYUYUTOUA/Stronghold-Protocol-Rhine/releases/latest) 下载小体积 **Rhine-Update-Tool-Windows.zip**，完整解压后双击 **联网更新.bat**，首次输入原安装目录。目录内应直接有 `bundle-manifest.json` 和 `runtime/node/node.exe`。

独立工具使用旧整合包内的 Node.js，无需另装运行环境；本次更新用的程序临时复制到安装目录外，避免自更新时被占用。成功后只记住安装路径，下次双击无需再输入。默认缓存位于 `%LOCALAPPDATA%\Stronghold-Protocol-Rhine-Updater`，保存下载文件和安装路径，不保存账号或令牌。

首次安装仍下载完整包。工具只支持带清单的莱茵 Windows x64 便携包；上游官方包、源码 ZIP 和自行拼装目录需另行迁移，不能直接作为更新目标。

## 跨版本与下载

兼容清单格式的旧莱茵包可以直接更新到最新正式版，不需要逐个安装中间版本。工具比较当前清单与最新完整清单，补充新增文件并处理已移除文件。未来如改变清单格式或需要特殊迁移，会在发布说明中明确，工具不会猜测覆盖。

只获取固定仓库 `YUYUYUYUYUYUYUTOUA/Stronghold-Protocol-Rhine` 的最新正式 Releases，不安装实验室、测试版或上游原版。下载的是完整 Windows x64 ZIP，**不是差分补丁**，当前需数百 MB 下载量和解压空间。校验一致的完整缓存可复用，下载中断时重试。

工具核对 GitHub 资源大小和 SHA256、`SHA256SUMS.txt`、包内源码提交及每个文件的哈希。ZIP 所有路径通过检查后才解压。网络不可达、校验失败或本地冲突时不会安装新文件；不需要 GitHub 登录。

## 保留哪些内容

| 内容 | 处理 |
| --- | --- |
| `scripts/service.env.cmd`、`.env` / `.env.*`、`.npmrc` 等本机文件 | 不覆盖、不读取内容、不上传 |
| `logs/`、`*.log`、`.cache/`、其它清单外文件 | 保留，不清空原目录 |
| 自定义脚本、规则或资源 | 新版官方内容未变化时保留；新版也改了同一文件时报告冲突并停止 |
| 昵称、音量、画质、技能和模组选择 | 保存在浏览器同源存储中，文件更新不会清除 |
| 房间与进行中的对局 | 位于服务器内存中，停服后无法恢复；先结束对局再更新 |

浏览器“同源”指**协议、主机和端口都相同**。`localhost:3000` 与 `127.0.0.1:3000` 是两份设置；换 IP、端口或公网域名也会显示另一份，不能据此判断设置被删。

`data/config.json` 等规则数据随版本更新，不是用户设置。资源索引 `data/local-assets.json` 与贴图也需同步：未修改的随版本更新；用户修改过且新版也有变化时报告冲突。保留 `.env` 不表示启动器会自动加载它。

旧清单中已移除、且本机仍与旧版一致的文件会先备份再删除；不会删除清单外文件。新增文件与用户自加文件撞名且内容不同也会停止。工具不修改开机任务、防火墙、隧道或认证策略。

## 命令行、离线更新与回退

以下操作均先关闭旧服务。同一安装一次只运行一个更新窗口。只检查最新版本，不下载整包或修改安装文件：

```powershell
& 'D:\Games\Stronghold-Rhine\联网更新.bat' --check
```

只下载、解压和完整预检，不安装：

```powershell
& 'D:\Downloads\Rhine-Update-Tool-Windows\联网更新.bat' --target 'D:\Games\Stronghold-Rhine' --download-only
```

可用 `--cache 'D:\Rhine-Update-Cache'` 指定安装目录之外的缓存位置。安装与缓存不能相互嵌套，不支持网络共享或 junction。

离线方式继续支持：把新完整包解压到临时新目录，再运行：

```powershell
& 'D:\Downloads\新包\更新旧版.bat' --offline --source 'D:\Downloads\新包' --target 'D:\Games\Stronghold-Rhine'
```

有冲突时窗口只列出路径，不输出文件内容。先备份、比较并合并自定义改动后再更新，不要跳过整个 `data/` 或 `scripts/`。

复制出错时工具尝试恢复已替换文件。更新期间断电或关闭窗口可能留下混合版本；保留 `.rhine-updates` 中的备份，先回退再重新更新。回退备份目录替换为更新窗口显示的实际路径：

```powershell
& 'D:\Games\Stronghold-Rhine\更新旧版.bat' --rollback 'D:\Games\Stronghold-Rhine\.rhine-updates\时间-编号'
```

回退核对备份及当前文件哈希，不强行覆盖更新后又修改的文件；程序回退不能恢复内存对局。新版稳定后可自行整理旧备份与下载缓存。

源码随包提供于 `scripts/rhine-online-update.mjs`、`scripts/rhine-online-update.ps1`、`scripts/rhine-online-update-runner.ps1` 及原有 `scripts/rhine-bundle-update.*`。
